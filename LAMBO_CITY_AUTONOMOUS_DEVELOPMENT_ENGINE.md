LAMBO CITY — AUTONOMOUS DEVELOPMENT ENGINE

1. PURPOSE

Build a continuous, AI-assisted development system that helps LAMBO CITY improve even when its owner is not playing the game or actively supervising development.

The owner is the creative director. The Autonomous Development Engine is the development team.

The engine must understand the LAMBO CITY North Star, inspect the existing project, identify opportunities, create development tasks, implement approved improvements, test its work, and continue improving the project.

This system is intended to grow with LAMBO CITY.

2. CORE OPERATING MODEL

The engine operates continuously in the background through a controlled development environment.

Its improvement cycle:

1. Observe the existing project.
2. Understand the current architecture and working features.
3. Identify opportunities and unfinished work.
4. Generate and prioritize development tasks.
5. Assign tasks to specialized development runners.
6. Implement focused improvements.
7. Test the changes.
8. Preserve working versions and record results.
9. Learn from feedback and previous outcomes.
10. Continue with the next eligible task.

The engine must not require the owner to provide every individual task.

It may independently discover and propose improvements that support the established LAMBO CITY vision.

3. CENTRAL DEVELOPMENT DIRECTOR

The central director coordinates all development activity.

Responsibilities:

* Understand the LAMBO CITY North Star.
* Maintain project-wide development priorities.
* Discover opportunities for improvement.
* Create and organize tasks.
* Assign tasks to specialized runners.
* Prevent conflicting development work.
* Track progress and results.
* Maintain development history.
* Learn from owner feedback.
* Produce understandable progress reports.

4. SPECIALIZED DEVELOPMENT RUNNERS

Each major project area receives its own development runner.

Initial teams:

Studio Development Runner

Responsible for:

* LAMBO CITY Studio.
* DAW development.
* MPC and instruments.
* Beat Lab.
* Recording and mixing.
* Original sound library.
* Audio export and project workflows.

World Development Runner

Responsible for:

* Buildings and environments.
* Streets and navigation.
* Lighting and atmosphere.
* World circulation.
* Performance and optimization.

NPC Development Runner

Responsible for:

* Character behavior.
* NPC interactions.
* Character movement.
* Environmental character activity.

Digital Real Estate Runner

Responsible for:

* Buildings and properties.
* Interior environments.
* Functional property interactions.
* Future property systems.

Entertainment Development Runner

Responsible for:

* Grand Stage.
* Music experiences.
* Events.
* Performance environments.
* Entertainment interactions.

The architecture must allow additional runners to be added without rebuilding the central engine.

5. AUTONOMOUS DISCOVERY

The engine must do more than execute a fixed task list.

It should continuously:

* Inspect existing features.
* Identify incomplete workflows.
* Discover missing connections between systems.
* Identify opportunities to improve realism.
* Identify usability and performance problems.
* Recognize duplicated or unnecessary functionality.
* Suggest new features that support the North Star.
* Create appropriately sized development tasks.

New tasks must be prioritized by value, dependencies, risk, and compatibility with the existing project.

6. CONTINUOUS BACKGROUND OPERATION

The development engine must operate independently of the game session.

Closing the website, leaving the game, or turning off the owner’s iPad must not stop an already-running background development process.

This requires a separate hosted development environment capable of running scheduled or continuous jobs.

The game itself must not need to remain open.

The system must preserve task progress so interrupted jobs can resume safely.

7. PROTECTED DEVELOPMENT ENVIRONMENT

The engine must never freely rewrite the live game.

All generated code changes must first occur in a separate development workspace or branch.

Required protections:

* Inspect before modifying.
* Make focused changes.
* Preserve existing functionality.
* Keep changes isolated.
* Run available tests and validation.
* Record changes and results.
* Reject unsafe or unsuccessful changes.
* Preserve the last known working version.
* Prepare successful changes for review and release.

The engine must not silently overwrite production code.

8. OWNER AUTHORITY

The owner retains final authority over LAMBO CITY.

Standing development permission may cover improvements within established project boundaries.

Special approval is required before:

* Spending money or activating paid services.
* Changing billing or payment systems.
* Changing security or access permissions.
* Deleting important project data.
* Making major architectural changes.
* Publishing significant changes to the live website.
* Introducing cryptocurrency, wallets, accounts, or multiplayer.
* Changing established landmarks or protected systems.

The engine must explain why special approval is needed.

9. LEARNING AND IMPROVEMENT

The system should learn from:

* Owner feedback.
* Successful implementations.
* Failed implementations.
* Testing results.
* Existing project architecture.
* Previous development decisions.
* Established project standards.

Corrections from the owner must influence future task planning.

The engine may improve its task instructions, planning methods, reusable development tools, and project knowledge.

It must not independently disable its safety controls or expand its own permissions.

10. ORIGINAL CONTENT

New music, sound effects, artwork, and other creative assets must respect LAMBO CITY’s original-content direction.

Third-party copyrighted material must not be introduced without authorization.

Any external generation service must be reviewed for cost, licensing, and usage rights before activation.

11. INITIAL IMPLEMENTATION ROADMAP

Phase 1 — Foundation

* Establish the development engine architecture.
* Define task structure and task states.
* Build the central development director.
* Establish development policies and permission boundaries.
* Establish progress tracking and task history.

Phase 2 — Studio Runner

* Connect the first specialized development runner.
* Inspect existing Studio architecture.
* Identify improvements without rebuilding working audio systems.
* Create isolated development tasks.
* Validate proposed changes.

Phase 3 — Background Execution

* Establish a separate hosted execution environment.
* Enable jobs to continue when the owner is offline.
* Add resumable tasks and execution monitoring.
* Evaluate service costs before activation.

Phase 4 — Quality Control

* Add automated checks.
* Add change history.
* Add recovery and rollback procedures.
* Add development reports.

Phase 5 — Expansion

* Add World, NPC, Real Estate, and Entertainment runners.
* Introduce cross-system coordination.
* Prevent conflicting tasks.
* Expand the task registry.

Phase 6 — Continuous Autonomous Improvement

* Enable recurring project inspection.
* Enable autonomous opportunity discovery.
* Generate and prioritize new tasks.
* Continue working through eligible tasks.
* Report progress to the owner.

12. TECHNICAL PRINCIPLES

The existing LAMBO CITY project is the foundation.

Preserve its existing Three.js and modular JavaScript architecture.

Do not introduce a new frontend framework or rewrite the game simply to accommodate the development engine.

The development engine must be separate from the live game runtime.

Private credentials and AI service keys must remain in a secure server-side environment and must never be exposed in browser code.

Design for desktop, iPad, and mobile compatibility.

Prefer modular, reusable components over one large development file.

13. FIRST DEVELOPMENT MILESTONE

The first working milestone is not unrestricted self-modifying AI.

It is a protected autonomous development foundation that can:

1. Read and understand the repository.
2. Understand the North Star.
3. Discover a useful improvement.
4. Create a structured task.
5. Assign it to the Studio Development Runner.
6. Work in an isolated development workspace.
7. Validate the proposed change.
8. Preserve the result and report progress.

Once this works reliably, the same foundation can support every other LAMBO CITY development team.

FINAL DIRECTIVE

LAMBO CITY must have a development system that grows alongside the project.

The owner establishes the vision.

The central director coordinates the work.

Specialized runners develop their respective areas.

Quality control protects the foundation.

The system continuously discovers opportunities to improve LAMBO CITY without losing the identity, functionality, or working systems that already exist.

THE GOAL: LAMBO CITY KEEPS DEVELOPING EVEN WHEN ITS CREATOR IS AWAY.

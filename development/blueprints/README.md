## Reading these drafts

- `partial`: some source implementation exists; end-to-end behavior remains unverified.
- `planned`: direction exists; implementation is not established.
- `discovery-needed`: candidate source paths exist, but the department lacks enough reconciled evidence to claim a capability.
- `cross-cutting`: the department defines standards used by all others.
- Every roadmap item and acceptance criterion is a draft proposal, not permission to modify production.
- Candidate source paths are inspection starting points, not confirmed exclusive ownership.

## Implementation convergence

Read `ALIVE_IMPLEMENTATION_CONVERGENCE_DRAFT.md` before combining ALIVE candidate branches. It compares the open implementation lineages, records the paid-service dependency gap, and defines the minimum local-first completion gates before Floor 2 work resumes.

The source-verification engine is `verifyDepartmentSources.mjs`. Its JSON and Markdown reports are generated by CI as the `lambo-city-department-source-verification` artifact. Static reachability is not runtime/device proof, and a test-file reference is not a passing test result.

## Local-first ALIVE foundation

PR #52 adds a browser-native local control plane through `development/runtime/createLocalAliveControlPlane.js` and `development/storage/indexedDbDevelopmentStorage.js`. It persists tasks and review decisions in the current browser profile without AI, Vercel Sandbox, PostgreSQL, or hosted queue dependencies. It is a control plane only; it does not execute code or sync records across devices.
